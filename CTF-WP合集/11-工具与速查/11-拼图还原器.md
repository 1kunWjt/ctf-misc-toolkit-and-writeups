# 拼图还原器 v1.0（Jigsaw Tile Reassembler）— 自建工具卡

> 分类：工具 ｜ 用途：CTF 图片碎片题（被切碎的二维码 / 被切块的照片）一键复位
> 位置：`D:\XiaoMibook\CTF学习\拼图还原器\拼图还原器.exe`

## 一、它解决什么问题

Misc 里最常见的"图片碎片"题型：把一张完整图切成 N×M 块并打乱文件名，只给你一堆 `1.png / 2.png / ...`。
人眼能拼，但 3×3 以上、或者碎片是二维码时，人眼会**拼错也会"看起来像"**——这时需要算法给一个可信解。

对应 WP：[10-拼图还原flag_3x3](../03-Misc-图片与隐写/10-拼图还原flag_3x3.md)。

## 二、怎么用（30 秒）

```
1. 双击 拼图还原器.exe
2. 把碎片所在【文件夹】整个拖进窗口（或框选所有碎片一起拖）
3. 程序自动判定网格并排序，窗口直接给结果
4. 「保存 PNG」或「复制图像」
   —— 复制到剪贴板后可直接粘进扫码工具识别二维码
5. 排错了 → 「手动微调」，点两个格子互换
```

快捷键：`A` 求解 · `Ctrl+S` 保存 · `Ctrl+C` 复制 · `Delete` 清空 · 滚轮缩放。

## 三、它靠什么排序（两条线索互相兜底）

### 3.1 边缘像素对齐：MGC 代价

对每一对相邻碎片，比较「甲的右边缘 / 乙的左边缘」（竖缝）与「甲的下边缘 / 乙的上边缘」（横缝）。
设跨缝跳变为 `d`，两侧向内的局部斜率为 `s1`、`s2`，代价取：

```
cost = mean( d² + 0.5 · (d − (s1 + s2) / 2)² )
```

这是 Gallagher 2012 提出的 **MGC（Mahalanobis Gradient Compatibility）** 的简化版。
要点是：真接缝处的像素跳变应当与两侧的天然梯度**一致**，而不是强行要求"严丝合缝"——
后者对带纹理的照片会系统性地排错位。

所有接缝代价之和最小的摆法，就是求解结果。

### 3.2 纯色边结构推断（二维码题的关键）

如果某张碎片有一条边整行/整列纯色（二维码四周的静区白边），那这条边**只可能落在整张画布的边界上**。
当「2 条纯色边 / 1 条 / 0 条」的碎片数量，正好等于 N×M 网格的

| 位置 | 数量 | 纯色边条数 |
|---|---|---|
| 角块 | 4 | 2 |
| 边块 | 2(N−2) + 2(M−2) | 1 |
| 内部块 | (N−2)(M−2) | 0 |

配额时，网格与朝向就被**唯一钉死**了——这一步比像素对齐更硬，所以先算它，再用 MGC 细化。

## 四、配套脚本

| 脚本 | 作用 |
|---|---|
| `jigsaw\proto_solve.py` | 原型求解器（先跑通算法再包 GUI） |
| `jigsaw\probe_edges.py` | 统计每块碎片的纯色边分布，判定网格配额 |
| `jigsaw\check_metric.py` | 校验 MGC 代价矩阵是否合理 |
| `jigsaw\make_tests.py` / `run_tests.py` | 造合成碎片做回归测试 |
| `jigsaw\verify_qr.py` | 还原后直接解二维码，验证结果对不对 |

## 五、赛场判断

```
拿到一堆等尺寸小图
 ├─ 张数是完全平方数（4/9/16/25） → 先按 N×N 试
 ├─ 纯色边碎片数 ≠ 4 / 边块数 → 网格不是方的，先数纯色边
 └─ 还原后像二维码 → 直接扫码；扫不出就放大 4 倍再扫（静区可能被切掉）
```

> 经验：二维码题的判据不是"看着像"，而是**能扫出内容**。扫不出来就当没拼对。
