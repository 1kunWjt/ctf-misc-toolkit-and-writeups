# 叠叠乐（jenga） — Writeup

> DASCTF · 分类：Crypto · 难度：★★★★☆

| 项目 | 内容 |
|---|---|
| 题目名 | 叠叠乐（jenga） |
| 分类 | Crypto / RSA · 部分私钥泄露 |
| 附件 | `task.py`（3.2 KB，源码 + 注释里的全部常数） |
| 一句话 | 私钥被写成 `d = K·Q + P`，三层泄露把 2048 bit 的未知量一路压到 40 bit，最后靠 XOR 的可分离性做 meet-in-the-middle |
| 结果 | `DASCTF{6a4ba557-4fe7-4874-8dad-40e880cb7717}` |

**最终答案**

```
DASCTF{6a4ba557-4fe7-4874-8dad-40e880cb7717}
```

## 一、题目长什么样（先建立直觉）

题目只给了一个 `task.py`，读下来三件事同时发生：

```python
p = getPrime(1024); q = getPrime(1024)
n = p * q
phi = (p - 1) * (q - 1)

K, Q, P = getrandbits(900), getrandbits(50), getrandbits(40)
Y = K * Q + P
e = inverse(Y, phi)          # ← Y 就是私钥 d
c = pow(m, e, n)

print(f"n = {n}\ne = {e}\nc = {c}\nQP = {Q^P}")

a, b, ct = getPrime(256), getPrime(256), getPrime(256)
kp = K>>256<<256             # K 的高位（低 256 位清零）
kt = K - kp                  # K 的低 256 位
hint = (a * kt + b) % ct

print(f"a = {a}"); print(f"b = {b}"); print(f"ct = {ct}")
print(f"hint = {hint >> 64}")   # 残差的高 192 位
print(f"kp = {kp}")
print(f"kt = {kt >> 64}")       # kt 的高 192 位
```

也就是说：**RSA 的公钥指数 `e` 本身就是私钥的模逆**，而私钥 `d = K·Q + P`。正常情况这是个 2048 bit 的秘密，但出题人把它拆成三块分别漏了一点：

| 泄露 | 内容 | 漏了多少 |
|---|---|---|
| `kp` | `K` 的低 256 位清零 | `K` 的 644 位高位 |
| `kt >> 64` | `kt` 的高 192 位 | 256 位里的 192 位 |
| `hint >> 64` | `(a·kt + b) mod ct` 的高 192 位 | 盖住 `kt` 剩下的 64 位 |
| `QP = Q ^ P` | 两个小数的异或 | `Q` 只 50 bit，`P` 只 40 bit |

本题实测规模：`n` 2047 bit、`e` 2045 bit、`kp` 900 bit、`a/b/ct` 各 256 bit。

## 二、思路总览

先给结论：**不需要格，也不需要 Coppersmith，四步都是"把未知量砍半"的初等技巧。**

```
第 0 层：QP = Q ^ P            -> Q 的高 9 位白送，未知量 90 bit -> 40 bit
第 1 层：hint >> 64 + kt >> 64  -> 2 维 HNP（二维格 CVP）补出 kt 低 64 位 -> K 完整
第 2 层：d = K*Q + P            -> XOR 可分离，2^40 拆成 2*2^20 的 MITM -> Q、P、d 全出
第 3 层：e*d - 1 = k*phi        -> 顺手分解 n（其实只是为了自证）
```

标题"叠叠乐"就是这个意思：每一层的输出刚好是下一层的输入，抽错顺序就塌。

## 三、逐步复现

### 3.1 第一步：`QP = Q ^ P` 能白送什么

`Q` 是 50 bit，`P` 是 40 bit，异或只影响 `P` 覆盖到的低位（`P < 2^40`，够不到 `Q` 的高位）：

```
Q 的高 9 位 == QP 的高 9 位 = 340     Q 的低 40 位 = x（未知）    P = x ^ (QP & (2^40-1))
QP = 374563570713029 (49 bit)         QP>>40 = 340               QP & (2^40-1) = 729617269189
```

所以 `Q ∈ [340·2^40, 341·2^40)`，`A = Q & ~(2^40-1) = 373833953443840`。

**这一步的价值**：原本 `Q`、`P` 两个未知数共 90 bit，现在只剩**一个** 40 bit 的 `x = Q & (2^40-1)`。后面所有搜索都只针对它。

### 3.2 第二步：2 维 HNP 补出 `kt` 的低 64 位

`kt` 的高 192 位是题给的，低 64 位（记作 `x64`）未知，而 `hint = ((a·kt + b) mod ct) >> 64`。把 `kt = kt_hi·2^64 + x64` 代进去，令 `A0 = (a·kt_hi·2^64 + b) mod ct`、`C = (hint·2^64 - A0) mod ct`：

```
a·x64 - y ≡ C (mod ct)，0 <= y < 2^64        L = { (a·x - ct·j, x) }
```

这是标准的隐藏数问题（HNP）：`ct` 是 256 bit、`x64` 只有 64 bit，上面的 `L` 就是要用的二维格。

真实解对应的格点 `(a·x - ct·j, x) = (C + y, x)` 到目标点 `(C, 0)` 的距离只有 `2^64·√2`，而该格的行列式是 `ct ≈ 2^256`，高斯启发式下最短向量约 `2^128`——**差了 64 bit，所以最近点唯一**，高斯约化 + 最近平面法一下就出。

```python
def gauss_reduce(b1, b2):                 # 二维格基约化（精确整数，不用浮点）
    while True:
        if _dot(b2, b2) < _dot(b1, b1):
            b1, b2 = b2, b1
        mu = _rdiv(_dot(b1, b2), _dot(b1, b1))
        if mu == 0:
            return b1, b2
        b2 = (b2[0] - mu * b1[0], b2[1] - mu * b1[1])

A0 = (a * (kt_hi << 64) + b) % ct
C  = ((hint << 64) - A0) % ct
b1, b2 = gauss_reduce((ct, 0), (a, 1))
v = cvp_2d(b1, b2, (C, 0))                # 最近平面 + ±3 邻域枚举
x64 = v[1]
assert ((a * ((kt_hi << 64) + x64) + b) % ct) >> 64 == hint    # 必须过这一关
```

真实输出：

```
[1] n = 2047 bit, e = 2045 bit
[1] kp = 900 bit, kt_hi = 191 bit (= kt>>64)
[2] kt 低 64 位 x = 0x0b549cd1ae091f19
[2] kt = 255 bit，K = 900 bit
```

**到这里 `K` 已经完全已知**（`K = kp + (kt_hi<<64 | x64)`，900 bit），并且用 `hint` 反向校验通过——不是猜的，是可验证的。

### 3.3 第三步（关键）：XOR 可分离，`2^40` 变 `2×2^20`

现在 `d = K·Q + P = K·(A + x) + (x ^ M)`，其中 `M = QP & (2^40-1)`。直接枚举 `x` 是 `2^40 ≈ 1.1e12` 次大整数运算：

```
[bench] 200000 iters in 1.31s -> 153043 cand/s
[bench] 2^40 = 1.100e+12 candidates -> 83.2 days
```

83 天，不能接受。于是把 `x` 劈成两半 `x = xh·2^20 + xl`，利用恒等式 `x ^ M = x + M - 2·(x & M)`。

关键观察：`x & M` 拆开后**低 20 位只由 `xl` 决定、高 20 位只由 `xh` 决定**（两段比特不重叠，所以"或"就是"加"）。于是

```
d = C + F1(xh) + F2(xl)
    C  = K·A + M
    F1 = (K+1)·xh·2^20 - 2·((xh<<20) & M)
    F2 = (K+1)·xl       - 2·(xl & M)
```

`d` 变成了"只含 `xh` 的一项 + 只含 `xl` 的一项"，**可分离**。

另一边，RSA 关系给出（`s = p+q`，`phi = n - s + 1`）：

```
e·d - 1 = k·phi = k·n - k·(s-1)
=> (e·d - 1) mod n = n - k·(s-1)，  且 0 < k·(s-1) < 2^1972 << n
```

也就是说**正确的 `d` 会让 `(e·d-1) mod n` 落在 `n` 顶端宽度 `2^1990` 的窗口里**。把它写成两张表相加：

```
S1(xh) = (e·C - 1 + e·F1(xh)) mod n
S2(xl) = (e·F2(xl))         mod n
条件： (S1 + S2) mod n  >=  n - W        (W = 2^1990)
```

于是把 2^20 个 `xl` 按 `S2 // W` 装桶，再拿 2^20 个 `xh` 去查相邻的三个桶。总代价 `2×2^20`，命中后做一次完整校验：

```python
table = {}
for xl in range(HALF):                                   # 2^20
    s2 = (e * (K1 * xl - 2 * (xl & M))) % n
    table.setdefault(s2 // WINDOW, []).append(xl)

for xh in range(HALF):                                   # 2^20
    s1 = (base + e * (K1 * (xh << 20) - 2 * ((xh << 20) & M))) % n
    a1 = (n - s1) % n
    b  = a1 // WINDOW
    for bb in (b, (b - 1) % nb, (b - 2) % nb):
        for xl in table.get(bb, ()):
            s2 = (e * (K1 * xl - 2 * (xl & M))) % n
            if 0 < (a1 - s2) % n < WINDOW:
                x = (xh << 20) | xl
                d = K * (A + x) + (x ^ M)
                ...  # 用 k = (e*d-1)//n 反推 phi，验证 s^2-4n 是完全平方
```

真实输出（本机 12 秒）：

```
[2] xl 表完成：1048576 个桶，用时 7.5s
[3] 扫描完成，用时 3.7s，命中候选 1 个
[4] x(kt 之外唯一未知量) = 489736143478
[4] Q = 374323689587318
[4] P = 944458204083
[4] d = K*Q+P = 949 bit, k = 946 bit, phi = 2047 bit
[4] Q ^ P == QP : True
[4] d == K*Q + P : True
[4] e*d % phi == 1 : True
[4] p*q == n : True (1024 bit / 1024 bit)
```

**注意"命中候选 1 个"**：窗口 `2^1990` 相对 `n` 是 `2^-57`，`2^40` 个组合的误报期望只有 `2^-17`，所以命中的就是真解，不需要人工挑选。

### 3.4 第四步：解出明文

有了 `d` 直接 `pow(c, d, n)`，再 `m.to_bytes(...)` 转字节（分解 `n` 只是为了自证，不是必需）：

```
[5] plaintext = b'DASCTF{6a4ba557-4fe7-4874-8dad-40e880cb7717}'
```

顺手验一下 `p·q == n` 成立，说明 `phi` 推对了、`d` 也推对了——整条链没有"凑出来"的成分。

## 四、关键知识点

| 概念 | 是什么 | 这题为什么用它 | 以后在哪还会遇到 |
|---|---|---|---|
| HNP（隐藏数问题） | 已知 `a·x mod m` 的高位，求低位盲区里的 `x` | `hint >> 64` 正是"高位给了、低位没给" | 任何"泄露 96/192 位残差"的随机数题 |
| 二维格 CVP | 二维格求最近向量，高斯约化后最近平面法即可 | 目标点距格点 `2^64`，格本身尺度 `2^128`，唯一解 | ECDSA nonce 泄露、LCG 高位泄露 |
| 连分数（Legendre 判据） | `|x - p/q| < 1/(2q²)` 则 `p/q` 必是收敛子 | 想直接把 `k/Q` 从 `e·K/n` 里读出来——本题**失败**，见第五节 | Wiener、Boneh-Durfee 的前置直觉 |
| XOR 可分离性 | `x ^ M = x + M - 2(x & M)`，按位切块后两半互不干扰 | 把 `2^40` 的枚举降成两个 `2^20` 表 | 任何"异或 + 大整数"的搜索题 |
| MITM + 桶哈希 | 两表按"同一前缀"装桶，再相邻桶配对 | 条件只要求低位落在窗口内，本质是前缀匹配 | 子集和、生日攻击、哈希碰撞 |
| 部分私钥暴露 | 私钥的某一段/某种结构被泄露 | `d = K·Q + P` 三层泄露层层剥 | Hashcat 类 RSA、Coppersmith 系列 |

## 五、踩坑与陷阱

| 坑 | 表现 | 怎么绕出来 |
|---|---|---|
| 用浮点做二维格约化 | `round(an/det)` 里 `an` 有 500 bit，float 只有 53 bit 有效位，约化结果全错，HNP 直接 `[FAIL]` | 改成纯整数 `_rdiv(u,v)`，一个浮点都不许出现 |
| 想用连分数一步到位 | 试过 `k/Q ≈ e·K/n`：`|e/n - k/Q|` 约 `2^-11`，而 Legendre 要求 `< 1/(2Q²) ≈ 2^-99`——差 88 bit。真实输出 `连分数收敛子扫完 32 个，没命中` | 原因是 `e·P` 这一项有 `2^2085`，比 `n` 还大，把线性近似彻底毁掉；必须先把 `P` 从方程里挪走（第 3.3 节的窗口 + MITM） |
| 直接枚举 `x` | `2^40` 次、每次 3000 bit 大整数除，实测 153043 cand/s → **83.2 天** | 必须找可分离结构，把 40 bit 砍成 20+20 |
| 窗口开太窄 | 残差真值约 `k·(s-1) ≈ 2^1972`，若按 `2^1970` 开窗会漏解 | 留 18 bit 余量取 `W = 2^1990`，误报率仍只有 `2^-57` |
| 以为要 Coppersmith | 先算了 Boneh-Durfee 的界：`d ≈ n^0.464`，而 BD 只到 `n^0.292`，直接放弃是对的 | 有结构泄露时别硬套格，先看能不能"分离变量" |

## 六、赛场 20 分钟行动清单

1. **第 0~2 分钟**：读 `task.py`，量出每个参数 bit 长（`n` 2047、`e` 2045、`kp` 900、`Q` 50、`P` 40）。先确认 `e·Y ≡ 1 (mod phi)`，即 `Y` 就是 `d`。
2. **第 2~4 分钟**：算 `QP >> 40`，写下"`Q` 的高位已知 + 一个 40 bit 未知量"，这是全局唯一瓶颈。
3. **第 4~10 分钟**：写纯 Python 二维格（高斯约化 + CVP），跑 HNP 拿回 `kt` 低 64 位。**必须用 `hint` 反向校验**，否则后面全错。
4. **第 10~18 分钟**：写 `x ^ M = x + M - 2(x&M)` 的可分离拆分，2^20 装桶 + 2^20 查表，命中后验证 `e·d % phi == 1`。
5. **第 18~20 分钟**：`pow(c, d, n)` 再 `m.to_bytes(...)`，交 flag。
> 超过 25 分钟还卡在"40 bit 怎么搜"，就别再调格了——先写 MITM 骨架，桶宽宁大勿小。
