## 一、题目长什么样（先建立直觉）

附件只有一个文件，名字叫 `message`，111,226,930 字节。前 200 字节长这样：

```
$GPGGA,104959,6559.999,N,08759.999,E,1,10,0.8,267.9,M,38.8,M,,*5C
$GPRMC,104959,A,6559.999,N,08759.999,0.0,0.0,070826,0.0,W*5D
$GPGGA,105000,6600.001,N,08800.014,E,1,10,0.8,267.9,M,38.8,M,,*5C
$GPRMC,105000,A,6600.001,N,08800.014,0.0,0.0,070826,0.0,W*5D
...
```

第一反应一定是"这是 GPS 轨迹，画出来就是图"。但有三处不自然，值得先记下来：

1. 经纬度精度只有 3 位小数（0.001 分 ≈ 1.8 米），而且**反复出现同一批数值**；
2. 校验和永远是 `*5C` / `*5D`，与内容无关——说明整个文件是**程序生成的**；
3. 时间字段从 `104959` 出发、走几十秒又回到 `104959`，像个计数器，不像真实录制的钟。

所以这题不是"读日志"，而是"**读一段被伪装成日志的编码**"。

## 二、思路总览

先把结论摆出来：文件结构已经完全摸清，语义没破。摸清的部分是：

```
1,717,389 行 = 841,830 × $GPGGA  +  841,830 × $GPRMC  +  33,729 × 分隔行
分隔行 = 20 个「—」 + 16 个「#」 + CR（77 字节，33,729 行字节级完全相同）
块 = 相邻两条分隔行之间的一段，共 33,730 块，每块 19~35 个 GGA 点
坐标 = 10 个簇（间距 0.015 分）× 每簇 5 个子档（间距 0.001 分）= 50 级
```

没破的部分：这些数字到底编码了什么。本篇把"已经排除的可能"和"下一步该走的方向"写清楚，避免后来者重复踩。

## 三、逐步复现

### 3.1 第一步：先确认"里面有没有另一个文件"

111 MB 的附件，第一怀疑对象是"套了个压缩包/图片在尾部"。逐字节扫一遍（`an1.py`）的结果：

| 检验 | 结果 |
|---|---|
| 非 ASCII / 控制字节 | 只有 `e2 80 94`（U+2014 破折号），出现 674,580 次 |
| PNG / JPEG / ZIP / RAR 头 | 0 个 |
| 行长度分布 | 66 B × 841,830；61 B × 841,829；77 B × 33,729 |
| 编码 | 纯 UTF-8 文本，无二进制段 |

结论：**没有任何封装文件**，它不是"图片藏在文本后面"那种题，全部信息都在文本结构里。

### 3.2 第二步：行类型与分隔块

按行首分类，四种行型（`an4.py` / `an8.py`）：

```
841,830  $GPGGA,...    ← 每行一个坐标点，唯一随时间变化的字段
841,830  $GPRMC,...    ← 与同秒 GGA 的坐标完全相同，冗余
 33,729  ————————————————################                ← 分隔行
```

分隔行的字节构成很有意思：77 字节 = 20 个 `—`（3 B/个 = 60 B）+ 16 个 `#`（16 B）+ CR（1 B）。20 + 16 = 36 个字符，看起来像"一条横线加一段刻度"，但**33,729 行全部字节级相同**，所以它只是分隔符，不承载数据。

于是文件被切成 33,730 个块（最后一块后面没有分隔行）。这块结构是本题唯一"看得见"的骨架。

### 3.3 第三步：验证"校验和隐写"这条路

第一版想法是"校验位藏着信息"。写脚本对前 2,000 行按 NMEA 规则算 XOR 校验（`$` 与 `*` 之间所有字节异或）：

```
checksum good/bad in first 2000: 0 / 2000
```

**全部对不上**，而 GGA 行固定 `*5C`、RMC 行固定 `*5D`。这说明作者根本没算校验和，它只是个"像 NMEA"的装饰。这条路当场排除，省下大量时间。

### 3.4 第四步：坐标只是个 50 级量化网格

把所有 GGA 的经纬度取出来（`an4.py`，落成 `lat.npy` / `lon.npy` / `tm.npy`），统计离散值：

```
gga points 841830
lat min/max 6559.998 .. 6600.137      unique lat 51
lon min/max 8759.998 .. 8800.137      unique lon 51
```

51 个离散值不是连续数据，而是**网格**。按"总分钟数 = int(v/100)*60 + v%100"换算后（`an7.py`），结构立刻清楚：

```
簇心：6600.000, 6600.015, 6600.030, 6600.045, ... 6600.135   → 10 个簇（步长 0.015 分）
子档：簇心 ± 0.001 × {−2,−1,0,+1,+2}                          → 每簇 5 档
```

`6559.998 / 6559.999 / 6560.000` 这三个值是**分钟进位造成的负数侧**（65°59.998′ = 66°00.000′ − 0.002′），不是额外的第 52 个值。经度同理（基准 88°00.000′）。

所以每个点其实只有四个整数：

```
(lat簇 0..9, lat子档 0..4, lon簇 0..9, lon子档 0..4)
```

也就是每点 10 × 5 × 10 × 5 = 2,500 种状态，约 11.3 bit。42 万个点乘起来是一大堆比特——**信息量绝对够，缺的是映射规则**。

### 3.5 第五步：关于"哪里有图片"——图是画出来的，不是提取的

这一点必须说清，因为它是最容易误解的地方。附件里**没有图片**；看到的那几张 PNG 是分析过程中自己画的：

| 文件 | 怎么来的 |
|---|---|
| `first300.png` | 取前 300 个点的（经度簇, 纬度簇）当 (x, y)，按顺序连线 |
| `first500_coarse.png` | 前 500 个点，粗网格渲染 |
| `b1.png` | 第一个块（19 个点）放大 30 倍 |
| `block1_coarse.png` | 第一个块按簇坐标渲染 |

渲染代码就是 `an6.py` / `an7.py`：把 `(oc, lc)` 映射到像素、用 `ImageDraw.line` 连成折线。因为坐标只有 10×10 簇，画出来只有 90×90 像素，结果是一片密集乱涂——**看不出字形**。

这一步的反面价值很大：它证明了"把坐标当平面坐标直接连线"这个最直觉的假设**不成立**。真实答案要么换了映射（例如某个维度当时间/索引），要么信息不在几何上而在数值序列里。

### 3.6 第六步：三个否证（都是本机实测）

摸完结构后，做了三次统计，把三条常见思路排掉：

**否证一：块不是"一个字一个块"**

如果每块画一个字，那么相同字符必然产生**完全相同**的块。实测：

```
blocks 33730
unique blocks 33730 of 33730   ratio 1.000
most common block counts: [1, 1, 1, 1, 1]
```

33,730 个块**两两不同**。文本里不可能 33,730 个字全不重复，所以"块 = 字符"这条路排除。

**否证二：块长只有 8 档**

```
block point-count histogram:
19:2096  21:4221  23:4198  24:10627  26:4387  28:4172  30:2026  35:2003
```

8 种长度、总和 841,830。块长是**受控的离散量**（没有 20、22、25、27 这些值），但它只有 8 档，单靠它最多编码 3 bit/块，撑不起 111 MB。它更像是"由另一个变量决定的结果"，而不是信息本身。

**否证三：时间字段只有 45 个取值**

```
unique time values 45
```

45 个取值就是从 `104959` 到 `105034` 的秒计数循环。每块从 `104959` 重新数，跨块不连续。也就是说时间轴是纯装饰，**唯一可能承载信息的只有坐标**（外加块长）。

## 四、关键知识点

| 概念 | 是什么 | 这题为什么用它 | 以后在哪还会遇到 |
|---|---|---|---|
| NMEA 0183 | GPS 文本协议，`$GPGGA` 定位置、`$GPRMC` 定最小定位信息 | 整题的"外壳"，决定该解哪个字段 | 车联网、无人机日志、轨迹取证 |
| NMEA 校验和 | `$` 与 `*` 之间所有字节 XOR，两位十六进制 | 用来判断数据是真实采集还是程序伪造 | 判断日志真伪的第一指标 |
| 量化网格 | 把连续量压到离散格点（簇 + 子档） | 本附件的坐标就是 50 级量化 | 隐写通道、编码题、传感器降采样 |
| 分钟进位 | `6559.999′` = `6600.000′ − 0.001′` | 处理"看起来多出来的第 52 个值" | 一切 ddmm.mmmm 格式解析 |
| 负结果取证 | 用统计否证排除假设（唯一性、取值数、重复率） | 三条否证省掉几天弯路 | 任何"结构清楚但语义不明"的题 |

## 五、踩坑与陷阱

1. **把 51 个唯一值当 51 级网格**。真实是 10 簇 × 5 档 = 50 级，多出来的 3 个值是分钟进位产物，按 51 级去对齐会整体错位。
2. **先画图再想映射**。直接按 (lon, lat) 连线得到的是乱涂；顺序（谁当 x、谁当 y、是否按块断开）没定之前，图没有信息量。
3. **以为有隐藏文件**。111 MB 让人本能地去找"尾部附加数据"，实测一个文件头都没有，纯文本。
4. **拿校验和做突破口**。全部不匹配，是装饰性的 `*5C` / `*5D`。
5. **用块长当唯一编码**。8 档 × 3 bit 撑不起数据量，块长更像派生量。
6. **把 PNG 当成附件内容**。`first300.png` 等四张图是脚本渲染的分析产物，不在原始附件里。

## 六、赛场 20 分钟行动清单

1. 看前 200 字节，认出 NMEA；立刻验证校验和是否成立（不成立 = 伪造数据）。
2. 统计行型与行长度，找出分隔行，切块。
3. 抽出经纬度，统计唯一值个数；若远小于点数，就是量化网格。
4. 换算成"总分钟数"，量出簇间距与子档间距（本题 0.015 / 0.001）。
5. 拿前 2~3 个块手工画出 (簇, 子档) 序列，先看有没有明显几何形状（直线/对角/回折）。
   > 超过 30 分钟还没看出几何形状，就转去统计块长、块内点序、GGA/RMC 差值这些非几何通道。

## 卡点与正解方向

**已确认的事实**

1. `message` 是纯 UTF-8 文本，111,226,930 B / 1,717,389 行，无任何封装文件头。
2. 行型只有三种：`$GPGGA` 841,830、`$GPRMC` 841,830、分隔行 33,729，加起来正好 1,717,389 行。
3. 分隔行字节级完全相同（20 个 `—` + 16 个 `#` + CR），把文件切成 33,730 块，每块 19~35 点。
4. 校验和是假的（固定 `*5C` / `*5D`），`GPRMC` 与同秒 `GPGGA` 坐标一致，时间字段只有 45 个取值循环——这三处都不承载信息。
5. 经纬度是 10 簇 × 5 子档的量化网格（间距 0.015 / 0.001 分），每点等价于 4 个整数、约 2,500 种状态。
6. 33,730 个块两两不同；块长只有 8 档（19/21/23/24/26/28/30/35）。

**卡在哪**

- 映射规则没定：`(lat簇, lat子档, lon簇, lon子档)` 四个整数怎么组成信息，缺一条判定性证据；
- 直接按平面坐标连线只能得到乱涂，说明"几何即图像"的假设不成立；
- 块与块之间没有重复模式，没法用"同块同字符"的方式反查码表；
- 因此没有拿到 flag，也不去猜一个"看起来像"的答案。

**正解方向（按性价比排序）**

1. **换轴**：把"簇"与"子档"分开看。簇可能是行列坐标（10×10 像素图，块长 19~35 恰好是"每块点的个数"），子档可能是灰度/位平面（5 档 ≈ 2 bit）。先把每块画成 10×10 点阵，而不是把整条轨迹连成折线。
2. **块长与簇耦合**：块长只有 8 档，先统计「块长 ↔ 首点簇」「块长 ↔ 末点簇」的联合分布。若块长由首末簇决定，那它就是结构而非数据，能反推编码方式。
3. **同一秒 GGA/RMC 差值**：目前抽样的两边坐标相同，但需要**全量**比对一次；只要存在系统性差值（±0.001 分），差值本身就是一条独立通道，而且 5 档正好对应四进制。
4. **按列重排**：把 841,830 个点按「第 k 个点」对齐成 33,730 × 25 的矩阵（或按块前补零成等长），再逐列看取值——很多"逐点乱、逐列有规律"的编码会在这一步露出来。
5. **优先复用开源工具**：这类题在中文赛里出现过（NMEA 轨迹当画板），找同题别的 writeup 验证"是否 10×10 点阵"这一条假设，比自己盲试快得多。

**一句话教训**

遇到 111 MB 的"传感器日志"，先花 10 分钟做**结构统计**（行型、分隔符、唯一值、重复率、校验和），比直接画图有效得多；四个统计量就能把大部分错误假设一次性否掉。
