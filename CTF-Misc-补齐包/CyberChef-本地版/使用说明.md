# CyberChef 本地版（v11.5.0）

给比赛用的离线版本。**双击 `启动CyberChef.bat` 就能用**，不要直接双击 `CyberChef.html`。

---

## 一、为什么之前「打开 html 有些功能会卡死」

这不是你操作的问题，也不是文件损坏，是 **CyberChef 的设计决定的**，而且官方已经明确回复「不修」。

### 1. 复现结果（本机实测，Chrome 156）

同一份 v11.5.0，同样 6 个操作，只有打开方式不同：

| 操作 | 所属模块 | 双击打开 `file://` | 通过 `http://127.0.0.1` |
| --- | --- | --- | --- |
| To Base64 | Default | ✅ 374 ms | ✅ 380 ms |
| **MD5** | Crypto | ❌ **卡死（15 s 无响应）** | ✅ 364 ms |
| **Regular expression** | Regex | ❌ **卡死** | ✅ 375 ms |
| **Entropy** | Charts | ❌ **卡死** | ✅ 371 ms |
| **Zlib Deflate** | Compression | ❌ **卡死** | ✅ 375 ms |
| Magic | Default | ⚠️ 能跑（但只能调 Default 里的操作） | ✅ 362 ms |

现象就是：页面能打开、操作列表能点、配方能拖，**一开始运算就永远停在 "Baking input 1..."**，
而且从此之后所有操作都不再有反应。这就是你说的「有些功能卡死」——「有些」= Default 模块之外的
那一半操作。

### 2. 根因

CyberChef 的运算全部在 Web Worker 里跑。为了让首屏加载快，它把操作拆成两类：

- **Default 模块（214 个操作）**：直接打包进 `assets/main.js`，随便怎么打开都能跑。
- **其余约 290 个操作**（Crypto / Ciphers / Hashing / Compression / Regex / Charts / Image / PGP / PublicKey / Shellcode …）：
  放在 `modules/*.js` 里，**用到时才由 Worker 用 `importScripts()` 去加载**。

源码位置 `src/core/ChefWorker.js`：

```js
self.loadRequiredModules = function(recipeConfig) {
    recipeConfig.forEach(op => {
        const module = self.OperationConfig[op.op].module;
        if (!(module in OpModules)) {
            self.sendStatusMessage(`Loading ${module} module`);
            self.importScripts(`${self.docURL}/modules/${module}.js`);   // ← 问题在这
        }
    });
};
```

用 `file://` 打开时，浏览器把页面当成**不透明源（origin = null）**，Worker 里再去
`importScripts("file:///D:/...")` 会被浏览器拒绝（跨源加载脚本）。
这一句抛异常后 Worker 不会回任何消息，而主线程只是在傻等 `bakeComplete`：

```js
case "bakeComplete":            // 永远等不到
    ...
    this.workerFinished(currentWorker);   // 所以 app.baking 永远是 true
```

结果就是 `app.baking` 卡在 `true`，而所有后续运算的入口都有 `if (this.baking) return;`
——**整个工具从此失去响应**。这和你描述的现象完全一致。

### 3. 官方结论

- Issue **#2871**：*Production build hangs (infinite spinner) when index.html is opened directly via file://*
  → https://github.com/gchq/CyberChef/issues/2871
- 官方回复（2026-10-10，已标记 **won't fix**）：
  > "Running CyberChef from a `file://` url is not supported for exactly this reason.
  > Modern browsers don't like loading assets from the local filesystem for security reasons...
  > it is trivial to serve by http."

官方 README 里的运行方式也只有两种：Docker 和源码构建后**通过 http 访问**（`http://localhost:8080`），
从来没有「双击 html」这条路。v10 时代是单文件 HTML，能凑合用；v11 起改成
`HTML + assets/ + modules/` 的分体结构，`file://` 就彻底不行了。

## 二、怎么用（30 秒）

1. 双击 **`启动CyberChef.bat`**
2. 会弹出一个黑色命令行窗口，显示地址（默认 `http://127.0.0.1:8787/`），浏览器自动打开 CyberChef
3. 用的时候**别关那个黑窗口**（它就是本地服务器，关掉服务就停了）
4. 用完直接关窗口即可

> 端口 8787 被占用时会自动往后找 8788、8789…，黑窗口里会显示实际地址，照那个地址打开就行。

### 30 秒自检（确认模块能加载）

打开后：

1. 在 **Input** 里输入 `aGVsbG8=`
2. 在 **Search** 里输入 `From Base64`，点一下加入配方 → Output 应显示 `hello`（这是 Default 模块）
3. 再试 **MD5**：Input 输入 `hello`，加 `MD5` → 应立刻出
   `5d41402abc4b2a76b9719d911017c592`（**这就是以前在 file:// 下会卡死的那个模块**）

只要 MD5、AES、Gzip、Entropy 这类操作能出结果，就说明一切正常。

## 四、比赛时的注意事项

- **完全离线**：v11.5.0 官方发布包，79 MB，所有依赖（含 OCR 的 tesseract 语言包）都在本地，断网可用。
- **不要再双击 `CyberChef.html`**：那样 Default 模块的 214 个操作能用，但 Crypto / Ciphers /
  Hashing / Compression / Regex / Image / PGP 等约 290 个操作会卡死，整个工具随后失去响应。
  一定要走 `启动CyberChef.bat`。
- **想固定地址**（比如收藏夹）：`启动CyberChef.bat 8787` 可指定端口。
- **多开/换端口**：再双击一次会自动换端口，互不影响。
- **卡住了怎么办**：`Ctrl+R` 刷新页面即可恢复（服务不用重启）。刷新后配方会丢，输入框内容通常还在。
- **处理大文件**：拖文件进 Input 区即可；如果某个操作很慢（如 Magic 深度 3 配大文件），
  用配方里的暂停/终止按钮，或先用 `Fork` 缩小范围。

### 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 黑窗口一闪就没 | Node.js 没装或被杀软拦了。装 Node.js（https://nodejs.org/）后重试；或看窗口里的报错 |
| 提示端口被占用 | 脚本会自动换端口；也可以 `启动CyberChef.bat 8899` 手动指定 |
| 浏览器没自动打开 | 手动复制黑窗口里的地址，例如 `http://127.0.0.1:8787/` |
| 页面打开但一直是转圈的加载语 | 说明访问的不是本地服务地址，检查地址栏是不是以 `http://127.0.0.1:` 开头 |
| 首次打开 Windows 防火墙弹窗 | 选「允许」或「取消」都行，只监听 127.0.0.1，不对外网开放 |

## 五、能不能挪走 / 换电脑

**能，整个文件夹一起复制走就行**（U 盘、D 盘、桌面、别的电脑都行）。

原理上本来就不依赖路径：

- `CyberChef.html` 里所有引用都是**相对路径**（`assets/main.js`、`images/...`），没有一处 `C:\` / `D:\` 硬编码（已在 13.6 MB 的 `main.js` 里核对过，`file:///`、`C:\\`、`D:\\` 均为 0 处）。
- `server.js` 以**自己所在的目录**为网站根目录，跟盘符、路径无关。
- Worker 加载 `modules/*.js` 的地址是从浏览器当前地址栏推导的，不是写死的。

**已实测**：把整个文件夹复制到 `D:\...\_移动 测试\CyberChef 副本`（带中文 + 空格），用里面的
`启动CyberChef.bat` 启动，`CyberChef.html`、`main.js`、`Crypto.js`、`Ciphers.js`、`PGP.js`、
OCR 语言包（10.9 MB）、字体全部正常返回 200。

三个前提：

1. **整个文件夹一起搬**，不能只拿 `CyberChef.html`（它必须和 `assets/`、`modules/`、`images/` 同级）。
2. **目标电脑要有 Node.js**（没有就装一个，或用 `.bat` 里的 Python 备用分支；两个都没有时脚本会提示）。
3. **放在本地磁盘或 U 盘，别放网络共享路径**（`\\NAS\share\...` 这种，cmd 的 `cd /d` 不支持把
   UNC 路径当工作目录）。也别在压缩包里直接双击，先解压出来。

另外两点小提示：

- 从 U 盘或网上下载的压缩包，解压后 Windows 可能对 `.bat` 弹「Windows 已保护你的电脑」，
  点「更多信息 → 仍要运行」；或右键文件 → 属性 → 勾「解除锁定」→ 确定。
- 换了端口（比如 8787 被占用自动变成 8788）后，左侧「Favourites」里的收藏操作会重置，
  因为浏览器是按「地址+端口」分别存设置的。想固定就用 `启动CyberChef.bat 8787`。
